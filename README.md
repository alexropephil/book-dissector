# 拆书 · 四维拆解 + 读者视角

把一部小说按四个维度拆开，看清它到底为什么好看：结构怎么搭的、规则怎么立的、人怎么活的、文字什么风格。

外加一个读者视角，模拟真实读者读这本书的感受。技术拆解回答“为什么好”，读者体验回答“好在哪、有多好”。

输出四份结构化报告加一份读者体验，给写作拆解、风格模仿、技法学习用。

## 四个维度 + 读者视角

| 维度 | 回答的问题 | 角色提示词 |
|------|-----------|-----------|
| 剧情 | 主线怎么搭？因果链自洽吗？节奏怎么控？ | `personas/plot.md` |
| 世界观 | 世界规则是什么？力量体系怎么运转？势力怎么分布？ | `personas/world.md` |
| 人物与情感 | 主角想要什么、怎么变？配角独立吗？关系网怎么织？ | `personas/character.md` |
| 文风 | 文字什么风格？对话分得出人吗？有没有 AI 味？ | `personas/style.md` |
| 读者视角 | 读者读到什么感受？哪里上头？哪里想弃书？ | `personas/reader.md` |

## 这套框架怎么来的

这五个 persona 不是泛泛的身份提示词，是从一套**写作诊断体系**里逆向提炼出来的完整工具。

写作时，你要检查爽点密度够不够、角色弧线卡没卡、文风有没有 AI 味；拆书时反过来，你问作者多久给一次爽点、弧线怎么走通的、天然的语言习惯是什么。同一个概念，正向是诊断自己，逆向是拆解别人。

关键是，这套 persona 带着**真实的判断标准**，不是空话：

- 剧情里写着“连续 3 章无钩子是失效线”“爽点间隔 3 到 5 章是标准”
- 人物里写着七种弧线故障的判定条件，以及“把开篇被欺负的场景放到现在，主角的选择还一样吗”这种可操作的检查
- 文风里写着 AI 味的十五种模式，和句长标准差这种量化指标

所以你用普通的“帮我分析这本书”问 AI，得到的是泛泛的通用分析；用这套 persona，得到的是有标尺、可复现、能落到原文的拆解。

## 快速开始

1. 准备目标书的 txt 文件
2. 打开 `personas/`，把五个角色提示词分别喂给五个 AI 会话（或依次喂给同一个 AI），各自附上书的正文和对应维度
3. 按 `templates/` 里的骨架收口，五份报告输出到同一个目录

## 目录结构

```
book-dissector/
├── personas/      # 四个维度 + 读者视角的角色提示词，可独立使用
├── templates/     # 五份输出模板，照着填
├── examples/      # 用公版书跑出的完整示例
└── docs/          # 拆书框架的方法论说明
```

## 适用场景

- 拆解一本让你上头的书，搞清楚它好在哪
- 学习某个作者的节奏、人设、文风
- 给自己的稿子建立可对照的分析基准
