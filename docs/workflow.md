# 拆书执行流程

一次完整拆书，分三步：准备、拆解、汇总。

## 第一步：准备

1. 确认目标书的 txt 文件（在拆书文库或指定位置）
2. 确定拆解范围：读多少章
3. 建立输出目录 `{书名}-拆书分析/`

### 读章策略

不是章数越多越好，是"覆盖关键节点"。一本网文的关键节点通常有四个：

- **黄金三章**：开篇留人（追读钩子、开篇）
- **第一个大冲突**：人物弧线起点、信念系统
- **金手指登场**：金手指平衡、反事实测试
- **第一次爽点兑现**：爽点密度、升级节奏的第一个完整周期

通常覆盖这四点需要前 20 章左右。拆书示例不需要全书，前 20 章足够展示框架威力。

## 第二步：拆解（五份 persona 协同）

顺序：读者视角先行，四维随后。按使用环境，有两种跑法。

### 读者视角先行

按 `personas/reader.md` 跑：素读 → 多类型读者模拟 → 八维度体验报告。

产出的"给技术拆解的备注"（读者觉得不对劲但说不清的地方），交给四维做定位参考。读者只报告"哪里不对劲"，不负责找"为什么不对劲"。

### 四维随后

**多 agent 环境（5 个会话并行）**：四个维度各占一个会话，互不依赖，可并行跑。

**单 agent 环境（1 个会话串行）**：一个 agent 依次扮演四个角色，每次加载一个 persona 文件、只跑一个维度。每个维度独立拆，但如果发现某个现象贯穿多个维度，把它明确标注为“跨维度观察”，不要因为“独立拆”就压掉它。

四个维度的拆解范围：

- 剧情 `personas/plot.md`：四颗粒度（全书结构 / 章节 / 场景 / 结局）
- 世界观 `personas/world.md`：九维度 + 两个专项
- 人物 `personas/character.md`：弧线体系 + A1-A7 健康度
- 文风 `personas/style.md`：风格形态 + AI 味逆向

## 第三步：汇总

五份报告收齐后：

1. 每份报告一句话亮点
2. 挑最值得学的 2 到 3 个点
3. 横向对比，找交集：什么手法四个维度都在夸、读者视角也上头
4. 标注报告存放位置

## 第四步：综合判断（跨维度）

五份报告各自拆完后，做一次跨维度的综合判断：

1. 有没有某个现象贯穿多个维度，但各维度只各自提了一句、没被合成完整判断？（比如“设定灌输多”在剧情、世界观、文风三份里都出现，合成一句就是“这本书的信息流风格就是灌设定”）
2. 有没有哪个维度的结论，和你的真实阅读冲突？把冲突说出来
3. 给写作者留一句“能带走的话”——这本书最值得学的那一点，用一句话说透

这一步是拆书的“货”，比评级表重要。

## 第五步：人读笔记（笔记师）

六份报告都写完后，用 `personas/note.md` 跑一份“真人阅读版”：

1. 读六份报告
2. 按 note.md 的要求，写成一份有立场、有温度、有节奏的笔记
3. 输出到 `07-拆书笔记.md`

这份是给人读的，和前面六份给 AI 读的报告是两种东西。

## 执行纪律

1. **忠实 persona**：严格按 persona 文件执行，不掺任何私有 agent 的人格或 skill。跑出来的东西，必须是用 persona 文件本身就能复现的。这是这套框架可信的前提。跨维度的现象允许、且应该被标注出来，这不违反忠实
2. **落到原文**：每个结论都要能指出原文位置，不空谈
3. **分段喂**：前 20 章约 6 到 8 万字，通读没问题，但喂给 persona 要分段，避免超上下文
4. **评级可选**：评级（S/A/B/C）是次要的，不想给就不给，给一句明确的判断比给等级更有用

## 输出元信息

每份示例必须附上元信息，交代它是怎么跑出来的：

- 拆解对象：书名 + 章节范围
- 使用 persona：对应 persona 文件路径
- 执行方式：单 agent 串行 / 多 agent 并行
- 模型：模型名称 + 版本

这四行是复现这份报告的必要参数。不标注模型，示例就是黑箱，看到的人无法判断自己的环境能不能复现同等的质量。
